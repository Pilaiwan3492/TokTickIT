The agent was strictly instructed to adhere to the pre-approved specifications and verify zero regression against the existing Lab 1 and Lab 2 codebases.

## 3. My Reflection on AI Use

Developing **Lab 3: TokTickIT** with the assistance of an advanced AI coding agent was an exceptionally enriching software engineering journey. It provided clear insights into how modern AI agents can accelerate the engineering lifecycle when governed by rigorous discipline, and where human engineering vigilance remains irreplaceable.

### 1. Accelerated Engineering Velocity through Strict Contracts (Spec DD)
The most striking benefit of using AI in this sprint was velocity without sacrificing architectural integrity. Because we invested upfront effort in creating comprehensive engineering contracts (`specification.md`, `api-spec.md`, `ui-spec.md`, and `tests.md`), the AI coding agent was given clear guardrails. When implementing complex features—such as migrating from the Lab 2 unauthenticated development selector to JWT-based session revocation and role authorization—the agent did not make arbitrary architectural assumptions. It followed the exact error codes (`PASSWORD_CHANGE_REQUIRED`, `SESSION_REVOKED`, `CANNOT_DEACTIVATE_SELF`), status codes, and database relationships defined in the specification. This contract-driven approach prevented regression across 140 backend tests and 98 frontend tests.

### 2. The Indispensable Need for Human Oversight in Security & Edge Cases
While AI agents excel at boilerplate implementation and implementing standard design patterns, **they cannot replace human engineering judgment when it comes to subtle security boundaries and race conditions**:
- **Last Active Administrator Protection**: During peer review of Issue 27, we identified that while the agent initially checked if a demoted user was an admin, it did not strictly guard against *deactivating* the last active admin (`{ isActive: false }`). Furthermore, in a concurrent environment, two administrators could simultaneously demote or deactivate each other. Human oversight identified this risk, prompting us to implement database-level transaction counting and add the concurrent race condition test `API-45b`.
- **Touch Target Hit Areas vs Bounding Boxes**: When implementing Issue 28, a naive touch-target assertion initially failed because native toggle switches (`<input type="checkbox">`) have a standard 16px height in Bootstrap, and buttons had inline heights. Human analysis recognized that switches are toggled via surrounding labels and that responsive CSS (`touch-targets.css`) was necessary to ensure primary controls met the $\ge 44\text{px}$ standard without breaking native semantics.

### 3. Conclusion
AI agents are transformative force multipliers in modern software development. However, their true value is unlocked only when developers act as rigorous architects and peer reviewers—defining clear specifications upfront, demanding test-driven verification, and actively interrogating edge cases to deliver secure, production-grade software.
